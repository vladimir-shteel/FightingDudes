# Справочник по конфигу — `data/config.json`

Справочник по каждому параметру `data/config.json` — построчно. Используйте его, чтобы быстро понять
«за что отвечает это число», настраивая значения во встроенном **Config Editor** (`` ` `` → ⚙ Config)
или редактируя JSON-файл напрямую.

Это именно *справочник*, а не туториал — за тем, как конкретно системы используют эти значения (формулы,
места вызова, имена файлов), загляните в [`architecture.md`](../architecture.md) в корне проекта. Оба
документа рассчитаны на совместное чтение: architecture.md объясняет механику, этот — объясняет ручки
настройки.

Разделы ниже идут в том же порядке, что и категории в Config Editor (General / Combat / Waves & Enemies /
Buildings / Units & Merging / Mining / Rewards), чтобы было удобно сверяться между документом и UI.

## Как читать таблицы

- **Path (путь)** — путь через точку от корня `config.json`, ровно в том виде, в каком он показан в
  тултипах и строке поиска Config Editor. `#` обозначает индекс массива (например,
  `fortressWaves.#.killGold` значит «`killGold` у любой записи в массиве `fortressWaves`»).
- **Type (тип)** — `number` (число), `string` (строка), `boolean` (булево), `object` (объект) или
  `array` (массив).
- **Enum (перечисление)** — если поле принимает только одно из фиксированного набора значений, они
  перечислены здесь. В Config Editor такие поля рендерятся как выпадающий список, а не как текстовое поле.
- Поля, которые являются просто именами/иконками/текстом для игрока (`name`, `icon`, `label`,
  `description`, `title`), как правило, не расписываются построчно в таблицах ниже — строку получают
  только механически значимые поля.

## 1. General (общее)

Глобальные параметры темпа игры: скорость симуляции, стартовые ресурсы, кривая цены найма воркеров,
пассивное золото.

| Path | Type | Description |
|---|---|---|
| `version` | number | Версия формата конфига. Не редактировать вручную — кнопки Save/Export в Config Editor проставляют её автоматически (см. **Версионирование** ниже). |
| `tickRateMs` | number | Длительность одного тика симуляции в миллисекундах. Меньше = плавнее, но выше нагрузка на CPU. Также задаёт задержку между кадрами анимации в главном игровом цикле. |
| `goldIcon` | string | Эмодзи, показываемая рядом с золотом везде в интерфейсе. |
| `startingGold` | number | Золото, с которым начинается забег. |
| `startingResources` | object | `{ resourceKey: amount }` — не-золотые ресурсы, с которыми начинается забег. Работают только ключи, уже существующие в ресурсном реестре (то есть реальные ключи ресурсов шахт). |
| `startingOre` | number | *Нижняя граница* специально для стартовой руды, дополнительно к (а не вместо) `startingResources.ore`. Итоговая стартовая руда = `max(startingResources.ore ?? 0, startingOre)`. |
| `unitBuyBaseCost` | number | Базовая цена в золоте за самого первого купленного резервного воркера, до применения масштабирования. |
| `unitBuyExponent` | number | Скорость роста кривой цены найма воркеров. Цена = `unitBuyBaseCost × unitBuyExponent ^ (суммарная «сила» воркеров)`, где «сила» — сумма `2^(уровень-1)` по всем резервным воркерам и воркерам на шахтах. |
| `productionMultipliers.rest` | number | Базовый множитель скорости добычи на шахте, пока воркер «отдыхает» (то есть **не** на боевой смене). `1.0` = полная скорость; `0.55` (значение по умолчанию) значит, что отдыхающий воркер производит на 55% темпа — воркеры на боевой смене берут свою скорость из `workerTraits.battleShift` (см. §5). |
| `passiveGoldPerSecond` | number | **Не читается ни одной системой.** Мёртвое поле — реально работающая ручка пассивного золота — `passiveGoldPerSecondPerUnlockedMine` ниже. Пока оставлено в схеме; не ждите эффекта от его изменения. |
| `passiveGoldPerSecondPerUnlockedMine` | number | Пассивный приток золота **за каждую разблокированную шахту**, выплачивается независимо от того, добывает ли кто-то активно. Существует исключительно для того, чтобы отправка всех воркеров в бой не приводила к софт-локу экономики. `0` полностью отключает эффект. |
| `passiveGoldPayoutIntervalSeconds` | number | Как часто (в секундах) выплачивается пассивный приток золота выше. |

## 2. Combat (бой)

Как боевой тик масштабируется по волнам, и как он *ощущается* момент-к-моменту.

### `combat` — формулы масштабирования по волнам

Все эти значения — **мультипликативные, начиная со второй волны** (волна 1 = без бонуса), что позволяет
разным архетипам врагов сохранять свою идентичность (хрупкий «runner» против танкового «armored»)
вместо того, чтобы HP всех архетипов сходилось к одному плоскому числу к 20-й волне.

| Path | Type | Description |
|---|---|---|
| `combat.hpScalePerWave` | number | Рост множителя HP врагов за волну. Например, `0.14` → HP врага на волне *n* = `baseHp × (1 + 0.14 × (n-1))`. |
| `combat.attackScalePerWave` | number | Рост атаки врагов за волну, та же форма формулы, что и у HP. |
| `combat.armorScalePerWave` | number | Рост брони врагов за волну — влияет только на врагов, у которых уже есть `armor > 0` в `fortressEnemies` (враг с базовой бронёй 0 никогда не получает прироста). |
| `combat.armorMinFraction` | number (0–1) | Минимальный порог урона сквозь броню. Итоговый урон = `max(raw × armorMinFraction, raw − armor)` — удар **никогда** не снижается ниже этой доли от исходного урона, какой бы высокой ни была броня цели. Это делает броню «мягким» контрприёмом (крупные удары всё равно проходят), а не полным иммунитетом. |
| `combat.unitAttackPerLevel` | number | Бонус атаки за **уровень здания-спавнера** для тренируемых им союзников — например, воины у казармы 3 уровня бьют сильнее, чем у казармы 1 уровня. Множитель = `1 + unitAttackPerLevel × (уровень_здания - 1)`. |
| `combat.unitHpPerLevel` | number | То же самое, что и `unitAttackPerLevel`, но для HP тренируемого юнита. |

### `combatEngine` — тонкая настройка боевого тика

Эти константы формируют *ощущение боя* — частоту пересчёта пути, физическое расталкивание, поведение
снарядов — а не то, насколько кто-то силён. Их изменение почти никогда не требует синхронизации с
остальным балансом.

| Path | Type | Description |
|---|---|---|
| `combatEngine.repathIntervalSeconds` | number (сек) | Как часто движущийся юнит пересчитывает путь до текущей цели. |
| `combatEngine.waypointArrivalDistance` | number (тайлы) | Насколько близко юнит должен подойти к точке пути, чтобы перейти к следующей. |
| `combatEngine.unitCollisionRadius` | number (тайлы) | Половина минимальной дистанции между двумя юнитами, после которой они расталкивают друг друга. Должен оставаться достаточно маленьким, чтобы противостоящие ближники всё ещё могли перекрываться в радиусе атаки друг друга — см. комментарий в коде `fortressBattleSystem.js`, если меняете дальности юнитов. |
| `combatEngine.unitPushStrength` | number | Насколько сильно перекрывающиеся юниты расталкиваются за тик. `1.0` полностью устраняет перекрытие за один тик; меньшие значения расталкивают постепенно (мягче в толпе). |
| `combatEngine.hitFlashSeconds` | number (сек) | Как долго юнит визуально «вспыхивает» белым после попадания. Чисто косметика. |
| `combatEngine.fieldVerticalMargin.top` / `.bottom` | number (тайлы) | Насколько далеко за верхний/нижний край поля юниту всё ещё разрешено стоять, прежде чем его вернут в границы. |
| `combatEngine.enemySpawnOffset.x` | number (тайлы) | Расстояние по горизонтали за правым краем поля, где спавнятся враги. |
| `combatEngine.enemySpawnOffset.yMargin` / `.yPadding` | number (тайлы) | Формируют разброс по вертикали точек спавна врагов: `y = random(0, FORTRESS_HEIGHT − yMargin) + yPadding`. |
| `combatEngine.squadSpawnSpacing` | number (тайлы) | Вертикальный интервал между юнитами, заспавненными одним отрядом (например, активка Rally Squad). |
| `combatEngine.spawnDistanceFromBuilding` | number (тайлы) | Насколько далеко перед своим зданием-спавнером появляется новый тренируемый/призванный юнит. |
| `combatEngine.projectileSpeed` | number (тайлы/сек) | Скорость полёта дальних атак — выстрелы турели, атаки дальних союзников, способности типа volley/frost. |
| `combatEngine.projectileHitRadius` | number (тайлы) | Насколько близко снаряд должен подлететь к цели, чтобы засчиталось попадание. |
| `combatEngine.turretDefaultRange` | number (тайлы) | Резервная дальность атаки для уровня турели, у которого не задано собственное поле `range` (см. §4). |
| `combatEngine.meleeEngageBuffer` | number (тайлы) | Дополнительная дальность сверх заявленного `rangeTiles` врага, при которой он всё ещё считается «в контакте» с целью-союзником — не даёт юнитам заметно останавливаться чуть-чуть не доходя до дальности удара. |
| `combatEngine.trapMineTriggerRadius` | number (тайлы) | Насколько близко враг должен подойти к зданию-ловушке (Trap Mine), чтобы её сработать. |
| `combatEngine.buildingContactRadius` | number (тайлы) | Насколько близко враг должен подойти к контуру здания, чтобы остановиться и начать его атаковать, вместо того чтобы продолжать идти ближе. |
| `combatEngine.bossAuraTickSeconds` | number (сек) | Как часто босс с механикой `aura` (см. §3) наносит импульс урона по площади. |
| `combatEngine.rangedAttackThreshold` | number (тайлы) | Союзники, у которых `rangeTiles` **больше** этого значения, стреляют снарядом (с учётом времени полёта); при значении ниже или равном — бьют цель напрямую, без задержки на полёт. |

## 3. Waves & Enemies (волны и враги)

### `fortressWaves` — массив, одна запись на волну, в порядке следования

| Field | Type | Description |
|---|---|---|
| `enemyCount` | number | Общее число врагов в этой волне. Должно совпадать с суммой `composition[].count` — читается интерфейсом отдельно для отображения прогресса, так что синхронизировать нужно вручную. |
| `spawnIntervalSeconds` | number (сек) | Время между спавном отдельных врагов внутри волны. |
| `killGold` | number | Золото, выплачиваемое **сразу за каждое убийство**. Большинство ранних волн используют `1`; поздние волны повышают это значение. |
| `demandResource` | string (enum) | Какой ресурс шахты получает `waveDemand.slotProductionMultiplier` (сам множитель — в §1/General, см. `waveDemand` ниже) на свои слоты в эту волну. **Enum**: любой ключ из `mine.resourceTypes[].key` (по умолчанию `wood`/`ore`/`iron`/`crystal`) — никогда `"gold"`, так как золото не является ресурсом шахты, и спрос на него молча ни на что не подействует. |
| `composition` | array of `{archetype, count}` | Группы врагов для этой волны. `expandComposition` перемешивает их round-robin в чередующуюся очередь спавна (так что волна с grunt×5 + runner×2 чередует типы по мере появления, а не спавнит сначала 5 grunt, а потом 2 runner подряд). |
| `composition[].archetype` | string (enum) | Какой ключ из `fortressEnemies` заспавнить. **Enum**: любой ключ из `fortressEnemies` (см. ниже). |
| `composition[].count` | number | Сколько особей этого архетипа в этой волне. |
| `type` | string | **Только для красоты — не читается ни одной системой.** `"boss"` используется по договорённости на боссовых волнах, но никем не проверяется; реально значим `isBoss` (ниже). |
| `isBoss` | boolean *(опционально)* | Управляет значком «BOSS» в UI предупреждения о волне (`ui.js`). По договорённости ставится вместе с `type: "boss"`, но функционально читается только это поле. |

### `fortressEnemies` — объект с ключом-архетипом

Одна запись на архетип врага. Ключ самого объекта (`grunt`, `runner`, …) *и есть* id архетипа, на который
ссылаются `fortressWaves[].composition[].archetype` и `mechanic.archetype` (для summon) в других местах.

| Field | Type | Description |
|---|---|---|
| `hp` | number | Базовые очки здоровья, до масштабирования `combat.hpScalePerWave`. |
| `attack` | number | Базовый урон атаки, до масштабирования `combat.attackScalePerWave`. |
| `cooldownSeconds` | number | Время между атаками этого врага. |
| `rangeTiles` | number | Дальность атаки в тайлах. `≤ ~0.5` читается как ближний бой; большие значения (2+) — дальнобойные атакующие. |
| `speedTilesPerSecond` | number | Скорость передвижения. |
| `armor` | number | Базовая броня, до масштабирования `combat.armorScalePerWave`. `0` = масштабирование брони никогда не применяется к этому архетипу, вне зависимости от волны. |
| `tag` | string (enum) | Функционально читается только буквальное значение `"boss"` (`ui.js` показывает полоску HP босса по условию `enemy.tag === "boss"`). Всё остальное (`normal`, `fast`, `armored`, `ranged`, …) — произвольная дизайнерская метка без поведения в коде. Выпадающий список в Config Editor для этого поля собирается из уже существующих у всех врагов тегов (плюс `"boss"`), так что придумать новый описательный тег всё ещё можно, вписав его в `tag` любого одного врага. |
| `mechanic` | object *(опционально)* | Присутствует только у боссов. См. ниже. |

**Варианты `mechanic`** (определяются по `mechanic.kind`, enum: `aura` / `summon` / `breach`):

| `mechanic.kind` | Доп. поля | Поведение |
|---|---|---|
| `aura` | `radius` (тайлы), `damagePerSecond` | Каждые `combatEngine.bossAuraTickSeconds` наносит `damagePerSecond` каждому живому союзнику **и** каждому зданию в радиусе `radius` тайлов. |
| `summon` | `archetype` (enum: любой ключ `fortressEnemies`), `intervalSeconds` | Спавнит одного врага указанного архетипа рядом с боссом каждые `intervalSeconds`. |
| `breach` | `damageMultVsBuildings` | Умножает урон этого врага **только по зданиям** (не по союзникам) на этот коэффициент. |

### `waveDemand`

| Path | Type | Description |
|---|---|---|
| `waveDemand.slotProductionMultiplier` | number | Множитель, применяемый к добыче слотов шахты, когда её ресурс совпадает с `demandResource` текущей волны. |

## 4. Buildings (постройки)

### `fortressBuildings` — объект с ключом-типом здания

Ключ самого объекта (`wall`, `turret`, `barracks`, …) — это тип здания, на который ссылаются
`fortressBuildings.*.levels[].unit`, ключи `buyCost`/`upgradeCost` в других местах и рантайм-поле
`building.type`.

| Field | Type | Description |
|---|---|---|
| `footprint` | array of `[x, y]` pairs | Смещения тайлов от точки размещения здания. `[[0,0]]` = 1×1; многотайловые здания (например, Big Wall — `[[0,0],[1,0],[2,0]]`) перечисляют все занимаемые смещения. |
| `unlockedByDefault` | boolean | Если `true`, этот тип здания доступен к постройке с 1-й волны независимо от `unlockWave`. |
| `unlockWave` | number *(обязательно, если не `unlockedByDefault`)* | Волна, на которой этот тип здания становится доступен к постройке. |
| `buyCost` | object `{resourceKey: amount}` | Базовая цена размещения первой копии. В итоговую цену также входит `buildingCostEscalation` (см. ниже) и любая `buildingBuyDiscount` из состояния забега. |
| `crystalMergeGated` | boolean *(опционально, по умолчанию false)* | Если `true`, мердж этого типа здания в верхние тиры дополнительно стоит кристаллов, по таблице `merge.crystalCostByLevel` (§5). Сейчас установлено у Barracks/Archery/Turret/Stables/Mage Tower — не установлено у Wall/Big Wall/Trap Mine/HQ. |
| `levels` | array | Одна запись на тир, индекс 0 = уровень 1. См. ниже. |

**Поля `levels[]`** (не каждое здание использует каждое поле — здание бывает либо *тренером* с
`unit`+`cooldownSeconds`, либо *турелеподобным* с `damage`+`range`, либо *ловушкой* с одними `hp`+`damage`):

| Field | Type | Применимо к | Description |
|---|---|---|---|
| `hp` | number | всем | HP на этом уровне (до добавления бонуса `baseHealthBonus` от награды текущего забега, если он есть). |
| `cooldownSeconds` | number | тренерам, турели | Время между спавном тренируемого юнита на этом уровне или между выстрелами турели. |
| `unit` | string (enum: любой ключ `fortressUnits`) | тренерам | Какой тип юнита тренирует этот уровень. |
| `damage` | number | турели, мине-ловушке | Урон за выстрел (турель) или при срабатывании (мина-ловушка). |
| `range` | number (тайлы) | турели | Дальность атаки. При отсутствии берётся резервное значение `combatEngine.turretDefaultRange`. |
| `upgradeCost` | object `{resourceKey: amount}` | каждому уровню, кроме последнего | Цена апгрейда **с** этого уровня на следующий. У последнего (максимального) уровня поля `upgradeCost` нет. |
| `active` | object *(опционально)* | только максимальному уровню | Способность, активируемая во время боя. См. ниже. Только верхний тир здания может её нести. |

**Поля `active`:**

| Field | Type | Description |
|---|---|---|
| `cooldownSeconds` | number | Перезарядка между применениями. |
| `cost` | object `{resourceKey: amount}` | Базовая цена в ресурсах за одно применение. Реальная цена растёт в течение боя — см. `abilityCostAccumulation` (§4 ниже) — так что это цена только *первого* применения в этом бою. |
| `effect` | object | Определяется по `effect.kind`. См. таблицу ниже. |

**Варианты `active.effect`** (enum для `effect.kind`: `buildingDamageBoost` / `spawnSquad` / `volley` /
`frost` / `shield`):

| `effect.kind` | Доп. поля | Поведение | Используется в (по умолчанию) |
|---|---|---|---|---|
| `buildingDamageBoost` | `multiplier`, `durationSeconds` | Умножает собственный урон здания на время действия. | Overcharge у турели |
| `spawnSquad` | `unit` (enum: ключ `fortressUnits`), `count` | Мгновенно спавнит `count` юнитов типа `unit` рядом со зданием. | Rally Squad у казармы, Charge у конюшни |
| `volley` | `count`, `damage` | Выпускает `count` снарядов по ближайшим врагам, по `damage` каждый. | Volley у стрельбища |

### `fortressUnits` — объект с ключом-типом юнита

Базовые характеристики юнитов, *тренируемых зданиями* (в отличие от резервных воркеров, которые
используют `unitLevels` из §5). На них ссылаются `fortressBuildings.*.levels[].unit` и
`active.effect.unit` (для `spawnSquad`).

| Field | Type | Description |
|---|---|---|
| `hp`, `attack`, `cooldownSeconds`, `rangeTiles`, `speedTilesPerSecond` | number | То же значение, что и у одноимённых полей `fortressEnemies`. |
| `splashRadius` | number (тайлы) *(опционально)* | Если задано, атаки этого юнита бьют по площади в этом радиусе вместо одиночной цели. Сейчас есть только у мага. |

Бонусы `attack`/`hp` по уровню приходят из `combat.unitAttackPerLevel`/`unitHpPerLevel`, применённых к
уровню *здания-спавнера* — сам `fortressUnits` хранит только базовые значения 1-го уровня.

## 7. Rewards (награды)

### `rewardDraft.cards` — весь пул наград за победу, единым плоским массивом

После каждой победы `rollUpgradeChoices` вытягивает **одну карту на категорию**, взвешенно внутри
категории по полю `weight`. Категория без карт (или с суммарным весом 0) просто не добавляет ничего в
этот драфт — игра не падает с ошибкой, игрок просто видит меньше 3 вариантов.

| Field | Type | Description |
|---|---|---|
| `id` | string | Уникальный id, на который ссылается выбор игрока. |
| `category` | string (enum: `permanent` / `temporary` / `oneShot`) | За какой из трёх слотов драфта конкурирует эта карта. `upgradeSystem.js` фильтрует и диспетчеризует именно по этим трём строкам — любое другое значение означает, что карта никогда не будет вытянута. |
| `title`, `description` | string | Отображаемый текст на карте награды. |
| `weight` | number | Вероятность быть вытянутой *внутри своей категории*, относительно других карт той же категории. По умолчанию `1`, если не указано. **`0` = никогда не выпадает — это и есть ручка редкости/исключения.** Не нормализуется в проценты — карта с `weight: 3` рядом с двумя картами `weight: 1` выпадает в 3 раза чаще каждой из них. |
| `effectText` | string *(только для «действийных» видов эффекта ниже)* | Вручную написанное описание эффекта. **Используется только для видов без единого осмысленного числового значения** (`promoteWorker`, `upgradeBuilding`, `unlockMineSlot`, `supplyDrop`, `massRepair`) — числовые виды (ниже) сами генерируют текст эффекта прямо из `effect.value`, так что этот текст никогда не разойдётся с реальным числом. |
| `effect.kind` | string (enum, 9 значений — см. ниже) | Какой именно эффект даёт эта карта. |

**Варианты `effect`** (enum для `effect.kind`):

| `effect.kind` | Доп. поля | Поведение | Для какой категории задуман |
|---|---|---|---|---|
| `goldMultiplier` | `value` | Навсегда умножает доход золота. | `permanent` |
| `productionMultiplier` | `value` | Навсегда умножает добычу на шахтах. | `permanent` |
| `baseHealthBonus` | `value` | Немедленно добавляет плоский HP каждому зданию крепости (задним числом, не только будущим постройкам). | `permanent` |
| `temporaryMultiplier` | `bonusKind` (enum: `production`/`damage`/`defense`), `value`, `durationWaves` | Ставит в очередь множитель, который активируется в **начале следующего боя** и угасает после `durationWaves` волн. | `temporary` |
| `promoteWorker` | — | Мгновенно повышает уровень одного подходящего воркера из резерва/шахты (учитывает привязанный к волне предел уровня — §5). | `oneShot` |
| `upgradeBuilding` | — | Мгновенно и бесплатно улучшает одно подходящее здание (учитывает кристалльный порог — не даст его перескочить). | `oneShot` |
| `unlockMineSlot` | — | Бесплатно открывает шахту или добавляет ещё один слот на уже открытой — но только если это уже доступно по волне; ни один порог не пропускается. | `oneShot` |
| `supplyDrop` | `goldInjection`, `resourceInjection` | Мгновенно выдаёт `goldInjection` золота плюс `resourceInjection` **каждого** ресурса шахт. | `oneShot` |
| `massRepair` | — | Мгновенно и бесплатно чинит каждое повреждённое здание до полного HP. | `oneShot` |

`category` и `effect.kind` — независимые поля: технически ничто не мешает скомбинировать эффект в стиле
`permanent` с `category: "oneShot"`, но карты по умолчанию всегда сочетают их осмысленно (эффект
`temporaryMultiplier` имеет смысл только при `category: "temporary"`, поскольку именно от этого зависит,
покажет ли `getCardDurationText` число волн вместо «Permanent»/«Instant»).

## Версионирование

Поле `version` верхнего уровня в `config.json` управляет системой оверрайдов Config Editor:

- **Save** / **Export** в редакторе проставляют `version = <версия поставляемого файла на момент загрузки
  страницы> + 1` перед записью/скачиванием — так что незавершённые правки дизайнера всегда понимаются
  как «на один релиз впереди того, что сейчас поставляется», сколько бы раз ни нажали Save за один
  присест.
- При загрузке локально сохранённый оверрайд (хранится в `localStorage` браузера, у каждого браузера
  свой) применяется, только если его `version` **строго больше** версии только что загруженного
  `data/config.json`.
- Практический эффект: когда вы берёте **экспортированный** дизайнером файл и кладёте его как новый
  `data/config.json`, устаревший локальный оверрайд в любом другом браузере — сохранённый ещё когда
  поставляемая версия была ниже — тихо выходит из игры при следующей загрузке, вместо того чтобы
  продолжать переопределять конфиг вечно. Никому не нужно помнить о нажатии «Reset to defaults».

Полный механизм — в `js/game/config.js` (`stampNextConfigVersion`, `getDefaultConfigVersion`) и в
разделе **Config Editor & Dev Tools** файла `architecture.md`.
